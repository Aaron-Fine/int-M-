### Verification objectives

Defined per plan §10:

- `MI-VER-PERF-001` — benchmark/observability.
- `MI-VER-PERF-002` — classifier agreement/rejection.
- `MI-VER-PERF-003` — catalog completeness/determinism/accessibility.
- `MI-VER-PERF-004` — rendering/cancellation/memory/browser budgets.
- `MI-VER-PERF-005` — optional acceleration capability/equivalence/fallback.

### Traceability matrix

Owning PR "PR 1" refers to the corpus, timing, and bounded-observability
change; "PR 2" refers to the allocation-free scalar kernel workstream
(plan §5 workstream B: `src/domain/orbit.ts` scalar core,
`src/render/classify-rows.ts` band-channel loop, and the
`poc/performance` pr2 microbench); "PR 3" refers to the common verifier
and semantic oracle change (plan §11: `src/domain/verifier.ts` frozen
acceptance policy `src-verifier-1.0.0`, verifier-gated acceptance in
`src/domain/orbit.ts`, and the oracle-adjudicated differential tests).
Requirements not touched by PR 1, PR 2, or PR 3 have no assigned PR yet.
MI-PERF-006 and MI-PERF-008 preserve the regression trace to the Phase 1 UX
requirements rather than superseding them: rendering responsiveness and
cancellation remain evidence for `MI-UX-003`/`MI-UX-007`, and catalog
presentation for `MI-UX-011`/`MI-UX-015`/`MI-UX-016`.
